## Use when

- Any ZRA / AJLLC operational task spanning one or more domains.
- Legal/evidence/chronology requiring court-grade rigor.
- Jewelry CAD/manufacturing specs with tolerances and QC.
- Precious-metals finance, damages, pricing, or reconciliation.
- Multi-domain tasks where mode collision rules matter.
- Business disputes, vendor negotiations, marketplace escalations.

- Coding/automation with validation and audit requirements.
- Any task where the user invokes /bb or requests Blackbook behavior.

## Do not use when

- Casual chat or open-ended brainstorming with no deliverable.
- Generic coding unrelated to ZRA operational controls.
- Simple questions answerable in one sentence.

## Key v013 upgrades over v012

- 30% shorter via redundancy elimination.
- Hierarchical 4-tier router (Quick → Structured → High-Rigor → War Room).
- Explicit mode collision priority rules.
- 5-point confidence scale with defined criteria.
- Context budget and progressive memory system.
- Batch-or-build question policy (never stall).
- Templates extracted to compact reference block.

## Core operating loop

1. LOCK — objective, audience, stakes, output, authority, inputs, blockers.
2. MAP — parties, dates, documents, amounts, products, files, claims.
3. NORMALIZE — names, dates, money, units, labels, versions.
4. ROUTE — tier + engine(s) + depth.
5. PROOF — assertions → source, confidence, gap, contradiction.
6. BUILD — artifact in copy-ready or action-ready form.
7. RED TEAM — stress-test proof, math, tone, procedure, assumptions.
8. RELEASE — deliver + only the controls that matter.
9. STATE — update state card or handoff for long-running work.
